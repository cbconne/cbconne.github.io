GitHub Action 8/26 后 cron schedule 出现长时间延迟

题外话：今天的封面图依然白嫖 ChatGPT 生成，但是显然右手的人体结构不对，但是反复几次让 AI 大人纠正也没什么作用，只能顺从了，反正大概是这个意思（）

之前写过我使用 GitHub Actions 定时执行任务获取每天游戏时长。

虽然官方明确说了 schedule 方式在高负载（尤其是整点时刻）时会有延迟，但最开始这个 action 的时间都还蛮准的，基本上都是十分钟级的延迟：

今年开始延迟逐渐增大，但也基本在半小时级别：

但是从 8/26 之后，延迟变得异常大并且非常不稳定：

统计一下趋势也非常明显：

具体原因找起来也很困难，反复排查了我自己的 actions 流程的问题之后+向无敌的 ChatGPT 大人询问之后确认就是 GitHub 的问题，8/26 之后使用 schedule 出现问题的 actions 还挺多的：

https://github.com/orgs/community/discussions/206019

https://github.com/orgs/community/discussions/207346

既然是 GitHub 的问题那就彻底没有办法了，找到 GitHub 相关的说明文档，GitHub 确实在 8/26 actions 出现问题之后进行了一些性能优化，有可能和定时触发的 actions 出现延迟有关联，但是也说不准……

只能等着看后面 GitHub 会不会修复或者给一个更明确的说法了。坦白来说都是白嫖的 GitHub 资源，如果以后确实都是这么个延迟那我也只能接受，毕竟我的任务对及时性要求不那么高，也犯不上为此另外想办法做另一个定时任务去触发这个 action。

如果后面延迟继续增长，劣化到无法正常完整这个任务的话，只能考虑采用其他第三方的定时任务来触发这个 action 了，比如：Cloudflare Workers Cron Triggers、cron-job.org 。
